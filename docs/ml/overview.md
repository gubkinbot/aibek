## Общие принципы

### Данные
- **TimescaleDB** как единое хранилище временных рядов — уже в стеке
- Все пайплайны данных должны быть воспроизводимыми и версионируемыми
- Качество данных проверяется автоматически перед обучением

### Модели
- Каждая модель имеет базелайн (наивный/эвристический метод для сравнения)
- Версионирование моделей: храним артефакты + метаданные обучения
- A/B-сравнение новой модели с текущей перед заменой

### Мониторинг
- Data drift — изменение распределения входных данных
- Prediction drift — изменение распределения предсказаний
- Алерты при превышении порогов деградации

### Безопасность
- ML-модели работают через тот же RBAC, что и остальная платформа
- Доступ к дашбордам и предсказаниям контролируется permissions
- Все действия с моделями (деплой, откат) записываются в аудит-лог

## Формат документов

Каждый проект описан по единому шаблону из 9 блоков:

1. **Цель и контекст** — бизнес-проблема, ML-задача, метрика успеха
2. **Данные** — источники, формат, объём, качество
3. **Базелайн** — как задача решается сейчас (без ML)
4. **Модель** — подход, архитектура, обучение
5. **Оценка** — офлайн/онлайн метрики, критерий годности
6. **Деплой** — serving, инфраструктура, мониторинг
7. **Риски** — технические, бизнесовые, этические
8. **Команда и ресурсы** — люди, железо, timeline
9. **Журнал решений** — лог ключевых решений (живая часть документа)

::: tip Журнал решений
Блок 9 — самый важный. Каждый раз, когда принимается существенное решение (выбор модели, отказ от фичи, изменение метрики), добавляйте запись с датой, контекстом и альтернативами. Через полгода это будет бесценным источником знаний.
:::
