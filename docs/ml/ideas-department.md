## 1. Цель и контекст

### Бизнес-проблема

АО «Узтрансгаз» — это тысячи сотрудников на десятках объектов по всему Узбекистану. У производственного и инженерного персонала ежедневно возникают идеи по улучшению процессов, снижению затрат и повышению безопасности. Но:

- **Нет единого канала** — идеи теряются в переписке, на совещаниях, в головах
- **Нет систематизации** — похожие идеи предлагаются повторно, нет приоритизации
- **Нет обратной связи** — авторы не знают, что произошло с их идеей
- **Барьер входа высок** — нужно написать обоснование, подготовить документ, найти руководителя
- **Полевые сотрудники без ПК** — операторы КС, обходчики трасс работают без компьютеров

### Видение

**Цифровой департамент идей** — это AI-powered система, которая:

1. **Собирает** идеи из любых каналов (веб, Telegram, голос)
2. **Помогает оформить** — AI-агент помогает структурировать идею, задавая уточняющие вопросы
3. **Анализирует** — автоматическая категоризация, поиск дубликатов, оценка потенциала
4. **Обогащает** — подтягивает релевантные данные, аналоги из базы знаний
5. **Маршрутизирует** — направляет идею ответственному подразделению
6. **Отслеживает** — прозрачный lifecycle от подачи до реализации

### ML-задача

Это не классическая ML-задача, а **LLM-based agentic system**:

| Компонент | Тип | Описание |
|-----------|-----|----------|
| Чат-агент | LLM + function calling | Диалоговый помощник для оформления идей |
| Классификатор | NLP (zero-shot / fine-tuned) | Категоризация по темам: безопасность, экономия, экология, процессы |
| Поиск дубликатов | Semantic search (embeddings) | Нахождение похожих ранее поданных идей |
| RAG | Retrieval-Augmented Generation | Обогащение идеи контекстом из базы знаний компании |
| Суммаризация | LLM | Краткое резюме и структурированная карточка идеи |
| Приоритизация | Scoring model | Оценка потенциала: влияние × реализуемость × стоимость |

### Заказчик

Управление стратегического развития, HR (вовлечённость персонала).

### Метрики успеха

| Метрика | Описание | Целевое |
|---------|----------|---------|
| Кол-во поданных идей | Идей в месяц | ≥ 50 в первые 3 мес |
| Конверсия в реализацию | % идей, дошедших до внедрения | ≥ 10% |
| Время до ответа | Среднее время от подачи до первого отклика | ≤ 3 рабочих дня |
| Вовлечённость | % сотрудников, подавших хотя бы 1 идею за год | ≥ 15% |
| NPS авторов | Удовлетворённость процессом | ≥ 7/10 |

## 3. Базелайн

### Текущий процесс

| Этап | Как сейчас | Проблема |
|------|-----------|----------|
| Сбор | Совещания, устные предложения, письма | Неструктурировано, теряется |
| Оформление | Автор сам пишет обоснование | Высокий барьер; многие не умеют/не хотят писать документы |
| Рассмотрение | Руководитель решает единолично | Субъективно; долго; нет прозрачности |
| Обратная связь | Часто отсутствует | Демотивирует подавать идеи |

### Базелайн для AI-компонентов

| Компонент | Базелайн | ML-модель |
|-----------|----------|-----------|
| Классификация | Ручная категоризация модератором | Zero-shot LLM / fine-tuned classifier |
| Поиск дубликатов | Ручной поиск модератором | Semantic search (cosine similarity на embeddings) |
| Оформление | Автор сам пишет | LLM-агент помогает через диалог |
| Маршрутизация | Модератор решает куда | Rule-based (категория → подразделение) + ML |

### Компоненты

#### 1. LLM (основной «мозг»)

| Параметр | Значение |
|----------|---------|
| Модель | Claude (Anthropic) или GPT-4 (OpenAI) |
| Режим | Function calling (tools) |
| System prompt | Контекст: роль помощника, знание о компании, тон общения |
| Температура | 0.3–0.5 (баланс между точностью и креативностью) |

Диалог с пользователем (пример):

```
Пользователь: На КС-5 часто забиваются фильтры после песчаных бурь,
              может поставить дополнительную ступень?

AI-агент: Интересная идея! Уточню несколько моментов:
          1. Какие именно фильтры забиваются — воздушные или масляные?
          2. Как часто это происходит — раз в месяц, в неделю?
          3. Сколько времени уходит на замену/очистку?

Пользователь: Воздушные, на входе в ГПА. После каждой бури, раз в 2 недели.
              Чистка занимает 4 часа, при этом ГПА работает на сниженной мощности.

AI-агент: Понятно. Я нашёл похожую идею, поданную в 2025 году для КС-3
          (ID-127). Там предлагали циклонный предфильтр — она была одобрена,
          но ещё не реализована.

          Оформляю вашу идею:
          ✅ Категория: Оборудование / Безопасность
          ✅ Потенциальное влияние: Высокое (снижение простоев ГПА)
          ✅ Направляю: Служба эксплуатации + связка с ID-127

          Хотите что-то дополнить?
```

#### 2. RAG (Retrieval-Augmented Generation)

| Компонент | Технология |
|-----------|-----------|
| Embedding model | `text-embedding-3-large` (OpenAI) или `e5-large` (open source) |
| Vector store | pgvector (расширение PostgreSQL) или Qdrant |
| Chunking | 512 токенов с overlap 50 |
| Документы | Регламенты, СТО, отчёты, протоколы совещаний |

#### 3. Semantic Search (дубликаты)

```python
# Поиск похожих идей
embedding = embed(new_idea_text)
similar = vector_store.search(embedding, top_k=5, threshold=0.85)
# threshold 0.85 — высокая похожесть (вероятный дубликат)
# threshold 0.70 — умеренная (связанная идея)
```

#### 4. Классификатор категорий

| Подход | Описание |
|--------|----------|
| **Этап 1:** Zero-shot (LLM) | Промпт: «Классифицируй идею: безопасность / экономия / экология / процессы / оборудование / кадры» |
| **Этап 2:** Fine-tuned | Дообучение на накопленных размеченных идеях (когда будет 500+ идей) |

#### 5. Scoring Model (оценка потенциала)

На первом этапе — LLM с промптом:

```
Оцени идею по 3 критериям (1–5):
1. Потенциальное влияние на бизнес
2. Сложность реализации (инвертировано: 5 = легко)
3. Оценка стоимости (инвертировано: 5 = дёшево)

Итоговый приоритет = (влияние × 0.5) + (простота × 0.3) + (дешевизна × 0.2)
```

На втором этапе — ML-модель на исторических данных (какие идеи были реализованы и принесли результат).

### Telegram-бот

Для полевых сотрудников без ПК:

```
/idea — начать подачу идеи
/status ID — проверить статус
/my — мои идеи

Бот поддерживает:
- Текст → прямая подача
- Голосовое сообщение → Whisper STT → текст → AI-агент
- Фото → OCR (при необходимости) + attachment к идее
```

| Параметр | Значение |
|----------|---------|
| Фреймворк | aiogram 3 (Python) или Telegraf (Node.js) |
| STT | OpenAI Whisper (API или self-hosted) |
| Язык | Русский + Узбекский (мультиязычный LLM) |

## 5. Оценка

### Метрики AI-компонентов

| Компонент | Метрика | Целевое |
|-----------|---------|---------|
| Классификация | Accuracy (top-1 категория) | ≥ 85% |
| Дубликаты | Precision (найденные дубликаты реально дубликаты) | ≥ 90% |

| STT (Whisper) | WER (Word Error Rate) для русского/узбекского | ≤ 10% |

| Метрика | Как измерять | Целевое |
|---------|-------------|---------|
| Completion rate | % начатых диалогов, завершившихся подачей идеи | ≥ 70% |
| Time to submit | Среднее время от начала диалога до подачи | ≤ 10 минут |

:::

### Lifecycle идеи

```
draft → submitted → review → approved → in_progress → done
                      ↓
                   rejected (с причиной)

Каждый переход:
- Записывается в аудит-лог
- Уведомление автору (email / Telegram)
- Если rejected — AI генерирует мягкий, конструктивный ответ
```

## 7. Риски

### Технические

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| LLM галлюцинации (ложная информация в RAG) | Средняя | Среднее | Чёткий system prompt; RAG с citation; модерация |
| Низкое качество STT для узбекского | Средняя | Среднее | Fine-tune Whisper на узбекских аудио; fallback на текст |
| Конфиденциальность данных при использовании внешнего LLM | Высокая | Высокое | PII masking перед отправкой в API; или self-hosted LLM |
| Prompt injection от пользователей | Низкая | Среднее | Input sanitization; отдельный system prompt; мониторинг |

### Бизнесовые

| Риск | Митигация |
|------|-----------|
| Сотрудники не будут пользоваться | Gamification (рейтинг, награды); поддержка руководства; простой Telegram-бот |
| Слишком много «мусорных» идей | Фильтрация на этапе AI-агента; мягкие уточняющие вопросы |
| Ожидание мгновенной реализации | Прозрачные SLA по этапам; автоматические статус-апдейты |

### Этические

- AI помогает **оформить** идею, но **не генерирует** идеи за человека
- Автор всегда указывается явно; AI-помощник — только инструмент
- Отклонение идеи формулируется конструктивно, с объяснением и предложением доработки
- Данные идей не используются для оценки эффективности персонала (без согласия)
